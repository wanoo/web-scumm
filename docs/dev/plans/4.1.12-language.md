# 4.1.12 « Language » — plan d'exécution

Programme §8. Le DSL évolue depuis les besoins vus par Gateways et Viewport ; une représentation intermédiaire unique
(`GameIR`) ; une empreinte de jeu précise (`GameFingerprint`) ; le socle **stabilisé** (plus de rupture gratuite) mais
le gel RC 4.2 attend Remix (D22).

## 1. État de départ

- `core/define.ts` : `defineGame`, `defineRoom`, `compileGame` → `CompiledGame` (gelé, `deepFreeze`) ; `core/content-ids.ts`
  (ids stables, `IdMap`) ; `tools/validate.ts` (1 183 lignes) ; `storyboardProblems` ; `tools/api-doc.ts` (signatures +
  stabilité) ; Studio : formulaires `src/studio/forms.ts`, undo (`api.undo`), `set_value` MCP ; `tests/gen/random-game.ts`
  (jeux générés seedés) ; `solve --audit-abstractions`.
- `tools/proof-cache.ts` : `stableJson`, `engineHash`, `gameSourceHash` (Node seulement).
- Pas d'IR distinct ; pas d'empreinte au runtime ; pas d'objectifs ni de journal de quêtes (seuls `checkpoints[id].goals`).

## 2. Décisions (ADR 0013 GameIR + GameFingerprint ; une ADR par famille de primitives ; D22)

- **GameIR** = la forme compilée, sérialisable, **canonique** (`canonicalJson`, voir 4.1.15 §4) de `CompiledGame` :
  salles, entités, règles, scripts, politiques Reality, objectifs, avec ids stables et provenance (fichier, ligne) ;
  consommée par runtime, solveur, replay, Studio, doc. Pas de code (les commandes personnalisées, minijeux, plugins
  sont du **code de confiance** référencé par id et haché à part).
- **GameFingerprint** `{ logic, trustedExtensions, presentation, engine }`, chaque composant SHA-256 (WebCrypto en
  navigateur, `node:crypto` en outil) sur une sérialisation canonique ; `logic` = IR ; `trustedExtensions` = source des
  commandes personnalisées + minijeux + plugins (hash des modules importés, fourni par le build : `sealBuild` plugin
  l'écrit dans `site.json`) ; `presentation` = manifeste d'assets + stage + voix ; `engine` = version + `prngVersion`
  (réservé, 4.1.14). Le speedrun (4.1.14) choisit par catégorie les composants exigés.
- **Primitives** : chacune passe par une ADR courte (0014+) avec la preuve que l'existant ne suffit pas (un jeu
  généré ou `reference` qui en a besoin), et atteint runtime + validateur + solveur + replay + Studio + MCP + doc
  (`test/4112-propagation`). Famille admise d'office : **objectifs** (`objectives` dans `GameDef`, `objectiveCompleted`
  dans le journal sémantique), car Time Attack en dépend. Candidates à instruire : attente de signal avec expiration
  et fallback hors ligne (Gateways l'a montré), séquences interruptibles et timelines (Viewport), états de dialogue
  nommés ; **refusées sans preuve** : rendez-vous temporels, événements du monde réel génériques.
- **D22** : socle DSL + IR stabilisés à la sortie ; `WorldVariant` réservé dans l'IR (`ir.variant: { mode: 'story' }`
  par défaut) pour que 4.1.15 étende sans réécrire ; migrations automatisées de `demo`, `reference`, `_template`,
  `signals`, fixtures ; `tests/api-surface.json` reste additif.

## 3. Contrats

```ts
export interface GameIR {
  schema: 1; engine: string; gameId: string;
  rooms: readonly IrRoom[]; entities: readonly IrEntity[]; rules: readonly IrRule[]; scripts: readonly IrScript[];
  objectives: readonly IrObjective[]; reality: IrRealityPolicies; variant: { mode: 'story' } | IrVariantSlot; // 4.1.15
  provenance: Readonly<Record<string, { file: string; line: number }>>; // par id
}
export interface GameFingerprint { logic: string; trustedExtensions: string; presentation: string; engine: string; }
export function compileIR(game: CompiledGame, o: { extensions: ExtensionHashes }): GameIR;      // pure
export function fingerprint(ir: GameIR, o: { presentation: AssetManifest; engine: string }): Promise<GameFingerprint>;
export function canonicalJson(v: unknown): string; // NFC, clés triées, pas de -0/NaN, bigint → décimal, entiers > 2^53 → chaîne
```

Objectifs : `GameDef.objectives?: Record<Id, { title: TextRef; done: Cond; optional?: boolean; parent?: Id }>` ;
`objectiveCompleted` émis la première fois que `done` passe vrai (évalué après chaque transition ; idempotent) ; journal
de quêtes dans le menu pause (`ui.objectives`), le solveur le voit comme un but (`100%` = tous les objectifs non
optionnels).

## 4. Branches, dans l'ordre

1. `docs/4112-adr` — ADR 0013 ; D22 ; la liste des primitives candidates avec, pour chacune, le jeu ou la fixture
   qui prouve le besoin (ou « refusée, l'existant suffit : … ») ; `docs/dev/DSL-STABILITY.md` (ce qui est stable, ce
   qui est encore additif, jusqu'à quand).
2. `feature/4112-canonical-json` — `core/canonical.ts`, **testé sur quatre runtimes** (vitest Node, et un e2e qui
   charge le même module dans Chromium, WebKit, Firefox et compare 50 valeurs limites : NFC/NFD, `-0`, `1e21`,
   `2n**64n`, clés unicode) ; `proof-cache.ts` l'utilise.
3. `feature/4112-ir` — `core/ir.ts` (`compileIR`), provenance (les ids portent leur `file:line` depuis
   `content-ids.ts`), `ir.variant` réservé ; le runtime consomme l'IR (pas `CompiledGame` directement) ou, si trop
   invasif, `CompiledGame` **dérive** de l'IR (décision à l'ouverture : mesurer le diff) ; `npm run ir -- --game demo`
   (dump lisible) ; test : `compileIR` déterministe (deux appels, même `canonicalJson`).
4. `feature/4112-fingerprint` — `fingerprint()`, WebCrypto/Node, `sealBuild` écrit `trustedExtensions` ; le menu
   pause affiche l'empreinte courte ; `tests/fingerprint.test.ts` : changer une règle change `logic` seul, changer
   un décor change `presentation` seul, changer une commande personnalisée change `trustedExtensions` seul.
5. `feature/4112-narrative` — objectifs (schéma, validateur : `done` satisfiable, `parent` acyclique ; solveur : but
   `100%` ; journal sémantique `objectiveCompleted` ; menu pause ; Studio formulaire ; MCP `set_value` sait les écrire) ;
   `demo` et `reference` gagnent 3–5 objectifs ; **ADR 0014 objectifs**.
6. `feature/4112-reality-primitives` — ce que Gateways a montré nécessaire (attente avec expiration, fallback hors
   ligne, consommation unique, consentement) : chaque primitive = ADR courte + propagation ; sinon rien.
7. `feature/4112-stage-primitives` — ce que Viewport a montré nécessaire (layers conditionnels, timelines
   interruptibles, cue audio) : même règle.
8. `feature/4112-studio-forms` — formulaires générés depuis le schéma zod de l'IR (`src/studio/forms-gen.ts`), diff
   avant écriture, undo/redo, vue IR + provenance (`api-browser` ou nouvel onglet), messages d'erreur fichier/id/champ.
9. `test/4112-propagation` — un test par primitive publique : définie dans un jeu fixture → vue par validateur,
   solveur (atteint le but), replay (même journal), Studio (formulaire), MCP (`get_room`/`set_value`), doc générée
   (`docs:generated`).
10. `docs/4112-generated` — `docs/en/DSL.md` + fr générés depuis les schémas + métadonnées (`tools/dsl-doc.ts`,
    marqueurs comme `api-doc`), testés contre le schéma.
11. `release/4.1.12` — migrations automatisées des contenus officiels (`web-scumm migrate` sait les appliquer) ;
    `tests/api-surface.json` additif ; UPGRADING.

## 5. Critères de sortie (§8.5)

- [ ] Aucune primitive publique ignorée par solveur, replay, validateur (test de propagation).
- [ ] Le Studio crée et modifie chaque primitive publique (test DOM par formulaire).
- [ ] Migrations des contenus officiels automatisées et testées (`upgrade-check --from=4.1.11`).
- [ ] Doc DSL générée ou testée contre le schéma.
- [ ] Socle DSL + IR stabilisés (DSL-STABILITY.md) ; `WorldVariant` réservé ; `canonicalJson` testé sur 4 runtimes.

## 6. Pièges connus

- `validate.ts` est à 1 183 lignes (exception) : chaque primitive y ajoute ; découper par famille
  (`validate/objectives.ts`…) avant d'ajouter.
- `tests/api-surface.json` : additif seulement ; un nom retiré est une rupture à documenter (UPGRADING), pas un
  « mouvement de baseline ».
- Les hash en navigateur sont asynchrones (WebCrypto) : `fingerprint()` est `async` partout ; ne pas cacher un
  `sha256Sync` Node derrière un polyfill.

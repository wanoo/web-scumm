# Lot 0 de 4.1.9 — la CI en trois niveaux : brouillon d'exécution

Complète `README.md` (lot 0, points 3 à 7). Ce brouillon donne la forme des jobs, du script `plan` et de l'agrégateur,
pour que l'exécutant parte d'un texte et non d'une page blanche. Il n'a pas tourné en CI : chaque job est à valider
par un run réel avant de toucher le ruleset (étape 5 de l'ordre sûr).

## 1. Le script `plan` (`tools/ci-plan.ts`, testé par `tests/ci-plan.test.ts`)

Entrée : la liste des fichiers changés (`git diff --name-only <base>...HEAD`, `fetch-depth: 0`). Sortie : un JSON de
booléens, écrit dans `$GITHUB_OUTPUT`, un par groupe de contrôles. Règles (la première qui s'applique) :

```ts
export interface CiPlan {
  code: boolean;        // src/, bridge/, tools/, scripts/, cli/, games/, package*.json, tsconfig*, vite.config.ts, vitest*.ts
  engine: boolean;      // src/engine/** sauf dom/render-*, dom/renderer.ts
  render: boolean;      // src/engine/dom/render-*.ts, renderer.ts, scene/**, room.ts, style.css, tests/visual/**
  reality: boolean;     // src/engine/reality/**, core/reality-runtime.ts, bridge/**, games/signals/**, scripts/e2e-reality.mjs
  saves: boolean;       // core/save.ts, core/migrate.ts, tests/fixtures/saves/**, tools/golden-save.ts
  packaging: boolean;   // scripts/pack.mjs, scripts/fresh-install.mjs, cli/**, games/_template/**, package.json "exports"/"files"
  pwa: boolean;         // vite.config.ts (bloc VitePWA), src/engine/boot.ts, dom/update.ts, dom/offline.ts, scripts/e2e-pwa.mjs
  audio: boolean;       // src/engine/dom/audio.ts, director.ts, tools/audio/**, games/*/audio/**, scripts/e2e-music.mjs
  docs: boolean;        // docs/**, README*.md, *.md à la racine
  windows: boolean;     // tout `code`, ou scripts/start.mjs, tests/run-tool.ts
  full: boolean;        // engine || un fichier partagé (package-lock.json, tsconfig.json, vite.config.ts hors bloc PWA, .github/workflows/ci.yml)
}
export function planFor(changed: readonly string[]): CiPlan;
```

Tests : une table « fichiers → plan attendu » (docs seuls → `{docs: true}` et le reste faux ; `bridge/src/store.ts` →
`reality`, `code`, `windows` ; `src/engine/core/engine.ts` → `engine`, `full` ; `package-lock.json` → `full`). Un
changement de `ci.yml` → `full` (on ne fait pas confiance au plan pour se valider lui-même).

## 2. `ci.yml` proposé (squelette)

```yaml
name: ci
on:
  pull_request:
  push: { branches: [main], tags: ['v*'] }
concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }
permissions: { contents: read }

jobs:
  plan:
    runs-on: ubuntu-24.04
    timeout-minutes: 5
    outputs: { plan: ${{ steps.plan.outputs.plan }} }
    steps:
      - uses: actions/checkout@<sha> # v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-node@<sha> # v7
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - id: plan
        run: echo "plan=$(npx tsx tools/ci-plan.ts --base=${{ github.event.pull_request.base.sha || 'HEAD~1' }})" >> "$GITHUB_OUTPUT"
        # sur main et sur un tag : tout vrai (`--all`)

  fast:                      # niveau 1 : 5–8 min, un seul job Node 22
    needs: plan
    runs-on: ubuntu-24.04
    timeout-minutes: 20
    steps:
      - checkout, setup-node, npm ci (retry ×3)
      - run: npm run changes -- --check --base=origin/main       # si pull_request
      - run: npm run lint:code && npm run tsc -- --noEmit && npx knip --no-progress
      - run: npm run test:coverage                               # une seule fois ; plus de test:node séparé
      - run: npx tsx tools/coverage-ratchet.ts                   # sans --strict : annote (::warning::), n'échoue pas
      - run: npm run build:game                                  # pas `build` (qui relance check)
      - run: npm run validate && npm run solve && npm run lint:content
      - run: npm run quality:baseline -- --check --dist
      - run: npm run audit:deps
        if: contains(fromJSON(needs.plan.outputs.plan).lock, true)
      - upload-artifact: dist/ (name: dist) # partagé par les lignes e2e

  chromium:                  # niveau 2, regroupé par navigateur
    needs: [plan, fast]
    if: fromJSON(needs.plan.outputs.plan).full || fromJSON(needs.plan.outputs.plan).render || fromJSON(needs.plan.outputs.plan).engine
    runs-on: ubuntu-24.04
    timeout-minutes: 40
    steps:
      - checkout, setup-node, npm ci, playwright install chromium
      - download-artifact: dist
      - run: npm run preview -- --port 5173 &  (+ curl wait)
      - run: npm run e2e -- http://127.0.0.1:5173/ --game demo --prod --save --axe
        continue-on-error: true
        id: full
      - run: npm run e2e -- … --generic --keyboard --save --no-indexeddb --axe
        continue-on-error: true
        id: keyboard
      - run: npm run e2e -- … --generic --lang fr
        continue-on-error: true
        id: fr
      - run: npm run e2e -- … --generic --renderer canvas && npm run e2e:visual -- … --renderer=canvas && npm run e2e:perf -- …
        continue-on-error: true
        id: canvas
      - run: npm run e2e:weight -- … && npm run e2e:visual -- … && npm run e2e:music -- … --only=offline|game|live
        continue-on-error: true
        id: extras
      - run: npm run e2e:pwa -- --serve=dist --update --interrupted --reinstall
        continue-on-error: true
        id: pwa
      - name: Summary                                             # le récapitulatif, puis l'échec s'il y en a un
        if: always()
        run: |
          for s in full keyboard fr canvas extras pwa; do echo "$s: ${{ steps.<s>.outcome }}"; done   # généré par un script
          [ "${{ steps.full.outcome }}" = success ] && [ "${{ steps.keyboard.outcome }}" = success ] && … || exit 1
      - upload-artifact (screenshots) if: failure()

  webkit:    # generic + clavier + a11y + music live + pwa --allow-skip ; même forme
  reference: # matrix browser: [chromium, webkit] ; needs fast ; if full || engine || render
  reality:   # xcheck + e2e reality chromium/webkit ; if full || reality
  pwa-firefox: # if full || pwa
  platforms: # windows (smoke) + node-24 (tests seuls, pas quality) ; if full || windows
  upgrade, second-game, fresh-install: # if full || saves || packaging
  mutation:  # inchangé : main, nuit, release-check, label full-ci

  pr-gate:                   # LE check requis par le ruleset
    needs: [plan, fast, chromium, webkit, reference, reality, pwa-firefox, platforms, upgrade, second-game, fresh-install]
    if: always()
    runs-on: ubuntu-24.04
    timeout-minutes: 5
    steps:
      - run: |
          # chaque job prévu par le plan doit être `success` ; un job `skipped` est accepté seulement si le plan ne le demandait pas
          node -e '…' # lit needs.*.result et le plan ; exit 1 sinon
```

Points d'attention :

- `cancel-in-progress` reste ; `needs: fast` fait qu'un échec rapide (types, tests) annule tout le niveau 2 : c'est
  le « fail fast » demandé, au prix de ~4 min de latence avant le niveau 2 (acceptable : le niveau 2 réutilise
  `dist/`, il économise un `build` par job).
- Les lignes e2e regroupées : `continue-on-error` par étape + récapitulatif, sinon le premier défaut masque les autres.
- Le job `pr-gate` doit **réussir aussi sur `main`** (le ruleset le lit sur la PR seulement, mais la cohérence
  compte) et être le seul nom requis après quelques runs verts.
- Le tag : `release.yml` reste déclenché par `workflow_run` de `ci` sur le tag tant que le point 8 (release accélérée)
  n'est pas fait ; le plan sur un tag = `--all`.

## 3. Ordre sûr, précisé

1. PR A : `tools/ci-plan.ts` + tests + le job `plan` (sortie seulement, rien ne le consomme) ; `fast` qui remplace
   `check` + `coverage` + `node-24`'s quality (le ruleset exige encore `check`, `coverage`, `node-24` : les garder
   comme alias ? Non : les renommer casse les checks requis. **Garder les noms `check`, `coverage`, `node-24` tant
   que le ruleset les exige** : `fast` s'appelle `check` ; `coverage` devient un job trivial qui attend `check` et
   réussit (ou mieux : l'utilisateur retire les noms du ruleset d'abord). Décision à prendre avec l'utilisateur
   avant la PR A.
2. PR B : les e2e regroupés par navigateur avec `needs: check` et l'artefact `dist`, les `if:` par plan,
   `pr-gate` en observation.
3. Ruleset (utilisateur) : `pr-gate` seul requis.
4. PR C : retirer les anciens jobs par scénario ; `coverage-ratchet --strict` en nuit et release seulement.
5. Mesurer : PR docs < 3 min, PR moteur < 10 min, runner-minutes par PR (cible < 15).

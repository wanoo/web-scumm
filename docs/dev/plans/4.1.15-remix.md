# 4.1.15 « Remix » — plan d'exécution

Programme §11. Variance contrôlée, déclarée par l'auteur, déterministe par seed, comprise par validateur, solveur,
sauvegardes, replay, Studio et Time Attack ; la roue de code diégétique (§11.13) ; **gel final du DSL et de l'IR à la
sortie** (D28, RC 4.2).

## 1. État de départ (après 4.1.14)

Réutilise : PRNG à flux + `Session.seed` + `prngVersion` ; `GameIR` avec `ir.variant` réservé ; `GameFingerprint` ;
`canonicalJson` (4 runtimes) ; journal sémantique et objectifs ; graphe d'énigmes (`puzzleGraph`, `toPuzzleSvg`) ;
`tests/gen/random-game.ts` ; `.cache/proofs` par hash ; `SaveEnvelopeV3` + `core/migrate.ts` ; signature JWS du Bridge ;
enveloppe speedrun + vérificateur ; Studio Rooms (sélection d'ancres depuis la scène) et Play (rejouer une seed).

Manque : ancres taguées, dimensions, contraintes, affectations couplées, `VariationManifest`, `WorldVariant`,
`SaveEnvelopeV4`, le solveur sur une instance, `remix`/`verify:variants`, le minijeu `code-wheel`, la version
imprimable, les catégories `Mystery`/`Daily`, l'engagement signé du Bridge.

## 2. Décisions (ADR 0018 VariationManifest/WorldVariant ; D25–D28 ; threat model seed)

- **ADR 0018** : `GameIR + VariationManifest + seed + algorithmVersion → WorldVariant` immuable, identique sur Node,
  Chromium, WebKit, Firefox ; aucun `Math.random()` sur ce chemin (lint Biome `noRestrictedGlobals` sur `src/engine/core`
  + test) ; `WorldVariant` stocké dans la sauvegarde (`SaveEnvelopeV4` ; migration : les sauvegardes 4.1.x reçoivent
  l'instance Histoire) et dans l'enveloppe speedrun ; jamais régénéré avec une autre version d'algorithme.
- **Une seed bien formée produit toujours un monde** : seed malformée ou version inconnue → erreur explicite ; manifeste
  impossible → **erreur de build** (`validate`), jamais erreur de partie. Catalogue fini : la seed sélectionne une
  entrée. Générateur ouvert : construction totale (prouvée par propriétés sur le domaine) ou publication refusée par
  `verify:variants`.
- **D25** : stratégie annoncée par mode (`catalogue` : toutes les instances prouvées, chacune gate de release ;
  `generator` : invariants testés exhaustivement sur petits domaines, par propriétés sur grands, échantillon publié
  de seeds prouvées ; la doc ne dit jamais « toutes les seeds sont prouvées » si échantillonnées).
- **D26** : Mystery Seed = engagement cryptographique (hash de la seed signé par le Bridge avant le départ, révélation
  après) ; Daily Seed = seed + règles signées par le Bridge, vérifiables hors ligne (la clé publique est dans le
  manifeste) ; le Bridge ne choisit jamais une seed après avoir vu des actions.
- **D27** : variance de présentation classée à part, hors espace du solveur (flux `cosmetic`).
- **D28** : gel final du DSL et de l'IR à la sortie : `tests/api-surface.json` et la baseline enregistrent le snapshot
  candidat 4.2 ; `DSL-STABILITY.md` passe tout en « frozen ».

## 3. Contrats

## 5. Critères de sortie (§11.12)

- [ ] Même seed → même instance et même hash sur quatre runtimes.
- [ ] Une ancienne sauvegarde recharge son affectation exacte après évolution du générateur.
- [ ] Aucun `Math.random()` sur le chemin logique (lint + test).
- [ ] Objets, personnages, indices, ordre : chacun une fixture réelle (`demo`/`reference`).
- [ ] Catalogue fini entièrement prouvé ; générateur ouvert avec couverture et limites publiées.
- [ ] Indice et solution jamais désynchronisés (propriété).
- [ ] Replay et paquet speedrun reproduisent le même monde.
- [ ] Studio : prévisualise, compare, exporte une seed.
- [ ] `reference` : Histoire + Remix + défi quotidien.
- [ ] Vingt seeds automatiques ; cinq humaines (non bloquant).
- [ ] Roue de code : même roue par seed sur tous les runtimes, alternative accessible, version imprimable.

## 6. Pièges connus

- L'espace du solveur explose si la variance logique n'est pas bornée : chaque dimension logique déclare un domaine
  fini ; `verify:variants` refuse un produit de domaines > 10 000 instances en mode `catalogue` (passer en `generator`
  avec échantillon).
- Les textes avec `{code}` passent par `i18n` : la propagation aux traductions est un test, pas une promesse.
- `SaveEnvelopeV4` = rupture 4.1 : UPGRADING, migration, golden save 4.1.15 ; `parseSave` accepte V3 et V4.
- Le PDF demande Pillow : optionnel, `doctor` le dit ; le SVG est toujours produit.

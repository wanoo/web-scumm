# 4.1.14 « Time Attack » — plan d'exécution

Programme §10. Un mode speedrun natif et vérifiable : catégories, RTA / IGT / Active IGT, splits sémantiques, paquet de
preuve chaîné, vérificateur headless isolé, ghosts, LiveSplit et OBS comme outils locaux, classement optionnel sur le
Bridge. Il distingue local / replay-valid / server-witnessed / moderator-verified et **ne promet pas** la détection
universelle de la triche.

## 1. État de départ

- `SessionLog` / `SessionEntry` (`t?` ms ignoré par le replay, `rnd[]`, `picks`, `digest`), `replay()` + `SessionFile`
  (`tools/replay.ts`), `SolveResult.steps` rejouables, `stateDigest` (FNV, non cryptographique), `core/timing.ts`
  (estimation de présentation : **pas l'IGT**), export de session (menu pause, dev panel, Studio Play), chunk paresseux
  (`reality-ui.ts`), patrons d'onglet Studio / commande CLI / outil MCP.
- Apportés par 4.1.11–4.1.13 : journal sémantique (`roomEntered`, `itemAcquired`, `objectiveCompleted`, `endingReached`…),
  `GameFingerprint`, `canonicalJson`, Bridge multi-tenant.
- Manque : `RunClock`, PRNG semé et versionné (`engine.random` non semé ; `rnd[]` est la trace), `SESSION_MAX = 5000`
  coupe une session longue, manifeste speedrun, enveloppe, vérificateur, worker isolé, overlay, LiveSplit.
- Conflits tranchés : D17 (SSE + fetch, pas de WebSocket **sur le Bridge**) → D23 : LiveSplit/OBS = outils locaux
  Node (`tools/speedrun/`), WebSocket local de l'outil, hors Bridge et hors PWA ; charte règle 10 (pas de scripting
  temps réel) → D24 : l'horloge **observe** le moteur et n'écrit jamais `GameState`.

## 2. Décisions (ADR 0016 horloge + enveloppe ; ADR 0017 verdicts ; D23 ; D24)

**Horloge** :

```ts
export interface RunClock {
  monotonicNow(): number;       // RTA locale : performance.now ; non reproductible
  logicalSteps(): bigint;       // compte des transitions du cœur (légalité)
  logicalTime(): bigint;        // microticks déterministes dérivés des constantes du contenu (classement IGT)
}
```

ADR 0016 retient (c) : **deux métriques** : `LogicalSteps` (une par transition, pour la légalité) et `LogicalTime`
(microticks : chaque commande du cœur a une durée logique déclarée, `core/timing.ts` devient la source de ces
constantes, versionnée `timingVersion` ; un `say` = f(longueur), une marche = f(distance / WALK_SPEED), un `wait` =
sa durée) ; Active IGT = `LogicalTime` moins les intervalles exclus par la catégorie (pauses, chargements, menus,
cinématiques, arrière-plan avec politique). `bigint` → **chaîne décimale canonique** dans toute enveloppe et tout
hash. Rechargement : la catégorie déclare `reload: 'invalidates' | 'allowed' | 'segment'`. L'horloge système
modifiable n'est jamais une autorité.

**PRNG** (dès ce lot, à flux séparés pour Remix) : xoshiro128** (documenté, 32 bits, portable), `prngVersion: 1`,
`Session.seed` (chaîne) ; flux dérivés `derive(seed, streamId)` pour `logic`, `cosmetic`, `minigame:<id>`,
`copy-protection` (4.1.15) ; `engine.random` tire dans `logic` ; `rnd[]` reste la trace, le vérificateur exige
l'égalité avec le PRNG semé. Les catégories `Random Seed` reposent dessus ; `Mystery`/`Daily` attendent 4.1.15.

**Journal chunké et chaîné** (remplace « lever `SESSION_MAX` ») : chunks de 500 entrées, stockés en IndexedDB au fil
de l'eau (`web-scumm-runs`), seul le chunk courant en mémoire ; chaque chunk porte `prevHash` ; index des splits ;
fermeture atomique du paquet ; récupération du dernier chunk validé après crash. Réutilisé par les longues sessions de
playtest.

**Chaîne de preuve** : `H0 = sha256(canonicalJson({ fingerprint: composants exigés, categoryId, rulesVersion, seed,
prngVersion, timingVersion }))`, `Hn = sha256(Hn-1 ‖ canonicalJson({ entry, rnd, events, logicalSteps, logicalTime }))`,
`finalProof = Hn` ; `finalStateHash` reste un contrôle supplémentaire. **Intégrité ≠ authenticité** : la chaîne prouve
qu'un journal n'a pas été altéré après coup, pas qu'il est honnête (un client peut la recalculer) ; seule
l'observation serveur ou humaine élève la confiance.

**Verdicts** (ADR 0017) : `valid`, `valid-unranked`, `invalid-category-rule`, `invalid-replay`, `modified-game`,
`missing-reality-proof`, `unsupported-version`, `inconclusive` (jamais traité comme valide) ; niveaux `local` →
`replay-valid` → `server-witnessed` → `moderator-verified`, affichés partout.

## 4. Branches, dans l'ordre

1. `docs/4114-adr` — ADR 0016, ADR 0017, D23, D24 ; politiques écrites : mods et extensions (composants exigés),
   anciennes versions du moteur (`unsupported-version` vs rejeu par version épinglée : **rejeu par version épinglée**
   via l'archive de la release, dans le worker), rétention et suppression des runs (90 jours par défaut, suppression
   à la demande), anonymisation des classements (pseudonyme, pas d'email), ghost sur cibles sémantiques.
2. `feature/4114-run-clock` — `core/run-clock.ts`, `timingVersion`, durées logiques par commande, `Engine.clock`
   observe (D24) ; tests : même session → mêmes `logicalSteps`/`logicalTime` (propriété sur 200 jeux générés) ; RTA
   non mocké dans le replay.
3. `feature/4114-prng` — xoshiro128**, flux dérivés, `Session.seed`, `engine.random` semé, `rnd[]` = trace ; test
   quatre runtimes (même seed → même suite, Node/Chromium/WebKit/Firefox) ; `prngVersion` dans l'empreinte `engine`.
4. `feature/4114-chunked-journal` — chunks + IndexedDB + chaîne ; récupération après crash (test : fermer la page
   mi-run (Playwright `page.close()`), rouvrir, le dernier chunk validé reprend) ; `SESSION_MAX` devient la taille
   d'un chunk ; playtests longs rejoués.
5. `feature/4114-manifest` — `GameDef.speedrun`, validateur (triggers existants, règles cohérentes), **test
   « catégorie complète définie en contenu seul »** (un jeu fixture ajoute une catégorie sans toucher `src/`).
6. `feature/4114-splits` — splits automatiques depuis le journal sémantique, PB, somme des meilleurs, avance/retard,
   split manqué sans corruption, routes import/export (`.wsroute`), éditeur et prévisualisation Studio (onglet Play).
7. `feature/4114-envelope` — `tools/speedrun/envelope.ts` (H0…Hn, `canonicalJson`, bigint en chaîne), export
   `.wsrun` depuis le menu pause et le dev panel.
8. `feature/4114-verify` — `npm run speedrun:verify -- run.wsrun`, commande CLI, outil MCP ; rejoue, recalcule
   IGT, compare, verdict motivé ; tests : chaque altération (temps, action, seed, règles, signal, hash, chunk) rejetée
   avec sa raison.
9. `feature/4114-reality-policies` — `forbidden` / `recorded` (scénario signé rejoué) / `live` (catégorie séparée) ;
   `missing-reality-proof`.
10. `feature/4114-records-ghosts` — historique local (IndexedDB), PB, meilleurs segments, abandons, notes de route ;
    ghost (curseur, salle, action, avance/retard, inventaire ; cibles sémantiques), désactivable ; import d'un témoin
    du solveur comme « route logique » (jamais un record humain) ; comparaison de deux routes.
11. `feature/4114-stream` — `tools/speedrun/overlay.mjs` (page locale HTTP/SSE pour OBS Browser Source ; complet,
    compact, transparent ; aucun secret) ; `tools/speedrun/livesplit.mjs` (export + autosplit WebSocket local) ; faux
    client LiveSplit en CI.
12. `feature/4114-leaderboard-worker` — soumission → Bridge (`POST /v1/runs`, multi-tenant) → file → **worker isolé**
    (processus séparé, CPU/mémoire/délai bornés, aucun secret du Bridge, aucun réseau, paquet de jeu approuvé par
    empreinte, sortie structurée signée) → verdict stocké ; jamais de rejeu dans le processus HTTP ; classement par
    catégorie, séparé par seed fixe/aléatoire, niveau de confiance affiché.
13. `feature/4114-studio-routes` — onglet Play : catégories, splits, routes, prévisualisation, export d'un run.
14. `test/4114-cross-browser` — même replay → même état final, même IGT, même `finalProof` sur Chromium, WebKit,
    Firefox (CPU ÷4) ; reprise après fermeture d'onglet, veille, perte réseau.
15. `release/4.1.14` — `4.1.14-rc.1` ; une tentative complète sur `reference` et son `.wsrun` publiés comme asset de
    la release (9e asset), vérifiés par `speedrun:verify` dans `release.yml` ; accessibilité et équité documentées
    (une option d'accessibilité n'est jamais une triche implicite).

## 5. Critères de sortie (§10.12)

- [ ] Une catégorie complète définie sans modifier le moteur (test).
- [ ] RTA, `LogicalSteps`, `LogicalTime`, Active IGT enregistrés ; reproductibles (propriété).
- [ ] Splits automatiques et reproductibles.
- [ ] Un run altéré est rejeté avec une raison précise (table d'altérations testée).
- [ ] Politiques Reality distinctes et vérifiables.
- [ ] LiveSplit et OBS depuis le build distribué (faux client en CI ; réels = humains).
- [ ] Records locaux hors ligne.
- [ ] Le classement ne fait jamais confiance au seul client (worker isolé, verdict serveur).
- [ ] Une tentative complète et son paquet publiés et vérifiés dans `release.yml`.

## 6. Pièges connus

- `bigint` ne se sérialise pas en JSON : toujours `canonicalJson` ; jamais `JSON.stringify` d'un objet qui en
  contient (test lint : `grep` de `JSON.stringify` dans `tools/speedrun/`).
- Le worker de vérification charge **l'archive de la version épinglée** : `scripts/pack.mjs` produit un tgz
  installable ; le worker fait `npm install --offline` dans un dossier temporaire ; mesurer le temps (budget 60 s).
- Le ghost ne doit pas révéler les énigmes : désactivé par défaut la première fois qu'une catégorie est jouée.
- Le set de mutation `core` grandit (`run-clock.ts`, `prng.ts`, `journal-chunks.ts`) : les ajouter au set avec leurs
  tests, mesurer avant de gater.

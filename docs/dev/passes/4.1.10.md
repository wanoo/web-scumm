# Passes, 4.1.10 "Constellation"

The programme's third release (§6 of `docs/dev/PLAN-4.1.8-4.1.15.md`, `docs/dev/plans/4.1.10-constellation.md`), each
exit criterion answered at the tag; then the passes only people can make (D12: reported, not blocking in 4.1.x;
blocking for 4.2.0 on every surface announced as supported, D18). The Postgres profile is `experimental` until a real
deployment.

## Not done, said as such

The Postgres load figures (the nightly's `bridge-load (postgres)` publishes the first); the `kill -9` test on Postgres
runs in CI only; a mutation run of the refactored `bridge.ts` (set `reality`, read on the next nightly) and of the new
`reality-store` set (not gated); retention on a SQL store; row-level security per tenant; a rate limit per connector
shared between instances; the load figures in BENCH-BRIDGE predate the busy-store change.

# Passes, 4.1.1 "Reality Bridge"

The release conditions of `docs/dev/PLAN-4.1-REALITY-BRIDGE.md` §13 (adopted as 4.1.1, D14): it may not ship while any
of these holds. At the tag, each one is answered by a test; then the passes only people can make (D12).

| # | It may not ship while… | At the tag |
|---|---|---|
| 1 | a modified, expired or other player's signal can reach `Engine.emit()` | refused before it is read (`tests/reality-protocol.test.ts`, 22 signed cases, the same verdict in Rust); an expired one is recorded as skipped, never emitted (`tests/reality-engine.test.ts`) |
| 2 | a connector can propose outside its Biscuit | refused: another game, player, source, signal, audience, after expiry, a widened attenuation (`tests/bridge-policy.test.ts`, the same verdict in Rust) |
| 3 | a duplicate can repeat a gameplay effect | applied once: the same delivery, the same webhook three times, once-per-game signals (`tests/reality-engine.test.ts`, `e2e:reality`) |
| 4 | a crash between reception, save and acknowledgement can lose a signal | delivered again and applied once after a crash before applying, after applying, after the save (`tests/reality-engine.test.ts`) |
| 5 | a replay needs the Bridge or holds a token | the session replays with the Bridge stopped; no token, capability or payload in a session or a save (`e2e:reality`, `tests/bridge.test.ts`) |
| 6 | the solver assumes an outside service is there | closed by default; scenarios and adversarial are explicit, and every result says its world (`tests/reality-proof.test.ts`, `npm run solve:reality`) |
| 7 | a 4.0 game without `reality` pays code or a request | the demo: no Reality client code in its first visit, nothing in its offline cache, no request; its first visit 120.7 → 121.2 KB for the hooks (the save's optional field, the boot's lazy import, the menu row); the code is a lazy chunk under `assets/reality/` |
| 8 | an earlier save no longer loads | every golden save from 3.0.0 to 4.1.1 loads and reaches the ending; `games/signals` has its own, with a link state |
| 9 | the Studio simulates by another path than production | the simulator feeds the same `RealityClient` after a real signature (`SignalSimulator`) |
| 10 | the Bridge can reach the Studio, the repository or the game's files | it imports only the protocol it shares with the player (`tests/boundaries.test.ts`); it knows a game by its manifest |
| 11 | rotation, revocation, retention and deletion are not documented | `docs/en/REALITY-OPS.md` (and `bridge rotate`, revoke, export, delete, tested) |
| 12 | the falsification and resumption tests fail in Chromium or WebKit | `e2e:reality` green in both; WebKit cannot reopen offline under automation (as `e2e:pwa`), Chromium does |

# Decisions (by the maintainer)

One line per decision, dated, written by the assistant who received it, never without a human decision. The maintainer
may write in French; the assistant adds the English next to it.

- **D1 · 2026-10-04** · v3 may break v2 (content schema, save format). Each break ships with its migration (charter rule 10). « La v3 casse la v2 : accepté. »
- **D2 · 2026-10-04** · Branch model: `main` = v2.5.0 until v3.0.0; `v3` = integration; `v3-<topic>` = one proposal; the first topic branch is Codex's beta commit `v3-beta1`. The local tag `v3.0.0-beta.1` was dropped: a beta is tagged on `v3` once approved.
- **D3 · 2026-10-04** · The maintainer arbitrates every disagreement; nothing is merged into `v3` with an open blocker. The exchange lives in `docs/dev/`, committed, in English.
- **D4 · 2026-10-04** · The goal of v3, set by the maintainer: ship online, with both assistants, a v3 worthy of a semi-professional engine. « Mets en ligne avec Claude une V3 qui est digne d'un engine semi-pro. » Every proposal and review measures itself against that bar: would a small studio trust it with a long game, offline, on a phone, with saves that survive updates?

- **D5 · 2026-10-04** · Offline: the whole game is cached after the first visit (`GameDef.offline: 'full'`, the default; `'nearby'` keeps the room-scoped warm-up only). Asked in LOG #3, decided with the 3.1 plan, shipped in `v3-offline` (3.1.0) and made truthful in `v3-offline-truth` (3.1.1). « Jeu complet hors ligne après la première visite. »
- **D7 · 2026-10-04** · After v3.0.0: `main` is the release branch (each `v3-<topic>` merges there as it passes its gates); D2's "`main` = v2.5.0 until v3.0.0" is closed. The WebKit CI job stayed experimental until three consecutive green runs on `main`, then gated (done in 3.1.0).
- **D8 · 2026-10-04** · The private reference game stays on engine 3.1.0 for good: no further sync, breakage accepted. It is no longer a gate (charter rule 7, AGENTS.md: amended by `v3-release-truth`). « Plus besoin de faire le jeu privé, tout le monde y a joué. »
- **D9 · 2026-10-04** · Cadence from 3.1.1 on: Claude implements one `v3-<topic>` / `v32-<topic>` branch at a time and merges it on green CI; Codex reviews afterwards (each release, or any branch it picks), and its findings open the next branch. The one-ball rule of the charter is kept for the exchange itself, not as a merge gate. Received with the approved 3.1.1 → 3.2 plan (LOG #26).
- **D10 · 2026-10-05** · A Canvas 2D scene renderer is allowed beside the DOM one, which stays the reference until the two agree (same targets, same logical results, visual baselines). The UI and every accessible target stay in the DOM. WebGL only for an effect Canvas 2D measurably cannot hold at 30 FPS; Phaser and a general physics engine are out (they would duplicate the engine's scenes, input, camera and assets, and a simulated collision cannot be saved, replayed or proved). Reverses "No canvas" in ROADMAP "Out of scope". From Codex's 3.4 plan, extended at the maintainer's request (LOG #55).
- **D11 · 2026-10-05** · After 3.3.0: 3.3.1 "Truth" (what 3.3 promised), 3.4 "Stagecraft" (asset graph, renderer contract, Canvas, layers and masks, walk topology, stage physics, voice production, Studio, a reference chapter), 3.5 "Score" (music director with stems, proof workers, inventory ownership). Each with its own exit criteria. « 3.3.1 + 3.4 + 3.5. »
- **D12 · 2026-10-05** · Human gates are reported, not blocking: the screen-reader pass, Safari offline, a real phone, playtesters, recorded voices, a signed tag. A release ships on its automated gates; its notes list each pass not done (`docs/dev/passes/<version>.md`). « Non, ils sont reportés et signalés. »
- **D13 · 2026-10-05** · The 3.4 reference chapter reuses the sample game's art (backdrops re-framed, furniture as foreground layers, masks traced on them): no new art. « Réutiliser l'art de la démo. »
- **D14 · 2026-10-06** · After 4.0.0 the project stays on the 4.1.x line for a while; 4.2 will be the final version. Codex's two plans ship in this order: **4.1.0 "Clarity"** (`docs/dev/PLAN-4.1.1-CLARITY.md`, behaviour-preserving, Biome as formatter and linter with one mechanical commit ignored by `git blame`), then **4.1.1 "Reality Bridge"** (`docs/dev/PLAN-4.1-REALITY-BRIDGE.md`) on the clarified code. 4.1.1 adds a public entry point, which SemVer would call a minor: a one-off exception the maintainer chose, recorded in `docs/en/SUPPORT.md` (additive, nothing of 4.1.0 breaks). « On va rester un moment en 4.1.XX car la 4.2 sera la version finale. » « Le plan doit inclure reality-bridge 4.1.1 et clarity 4.1.0. » « Biome complet. »
- **D15 · 2026-10-06** · Reality Bridge's signed envelope: a compact JWS (`EdDSA`, `kid`), verified by WebCrypto in the player, no library (381 bytes gzipped; Ed25519 present in Node, Chromium and WebKit). Proposed with the 4.1.0/4.1.1 plan the maintainer approved, confirmed by the spike (`docs/dev/reality-spike.md`).
- **D16 · 2026-10-06** · Biscuit on the Bridge only: `@biscuit-auth/biscuit-wasm` in production, Biscuit's official samples cross-checked against the Rust crate in CI. Same origin as D15.
- **D17 · 2026-10-06** · Delivery to the player: Server-Sent Events, plus an HTTP fetch by cursor giving the same events; no WebSocket. Same origin as D15.

- **D18 · 2026-10-07** · After 4.1.7 the project does not go to 4.2.0 "Finale": it runs the programme `docs/dev/PLAN-4.1.8-4.1.15.md` (French, the source of the decisions; `docs/dev/PROGRAM-4.1.md` is its English summary): 4.1.8 Foundation Reset, 4.1.9 Gateways, 4.1.10 Constellation, 4.1.11 Viewport, 4.1.12 Language, 4.1.13 Proof at Scale, 4.1.14 Time Attack, 4.1.15 Remix, then **4.2.0 "Stable World"** (the compiled package on npm, the narrower host API, the signed tag: what "Finale" planned). From 4.1.8 the 4.1.x line is an **incubation line**: no production game depends on the engine (D8), so a release may break a public name or a format when the programme needs it, each break documented with a migration of the bundled games and saves; the DSL's core is stabilised in 4.1.12 and frozen after 4.1.15; 4.2.0 restores strict SemVer. Human passes stay reported, not blocking, for 4.1.x (D12) and become blocking for 4.2.0 on every surface announced as supported. Each pull request is read by a second automated context (`/code-review`) before it merges: a second reading, not an independent review. The riskiest versions (4.1.8, 4.1.10, 4.1.11, 4.1.14, 4.1.15) get a release candidate (`-rc.1`, a GitHub pre-release) before their tag. « Propose un plan pour mener la release 4.1.14 » « Inclus dans le plan aussi la v4.1.15 » « Verdict : GO »

- **D20 · 2026-10-07** · The Reality Bridge's storage and delivery, from the programme's §6 (D18) as executed by `docs/dev/plans/4.1.10-constellation.md`: **SQLite is the `local` profile** (`node:sqlite`, one machine, several processes allowed; the default of `bridge init` once the engine requires Node 22.13, until then `--store=sqlite`), **Postgres the `distributed` profile** (`experimental` until a real deployment), **the JSON-lines journal an import and audit format** (`bridge migrate --from jsonl --to sqlite`; a 4.1.9 configuration still serves from it). Delivery is **at least once, applied idempotently, one logical effect**: the database is the source of truth of the fan-out, `LISTEN/NOTIFY` or a short poll only wakes an instance. `trust-proxy` takes an **allowlist** of proxy addresses or networks, never "any peer". `SignalV2` retained (ADR 0010), the store behind `RealityStore` (ADR 0009). « Verdict : GO » (the programme, D18).
